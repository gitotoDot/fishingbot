# Requirements

## 1. 목적과 범위

[차터](charter.md)의 전체 목표를 바탕으로 [Problem Definition](problem.md)의
시작 시 팔 보정·장난감 보유 분기 및 3단계 동작을 수행하는 제어 소프트웨어를 개발하고 MuJoCo 시뮬레이션에서 검증한다.
시뮬레이터는 MuJoCo를 필수로 사용한다.
이번 단계는 카메라 인식, 이동부, 로봇팔, 집게 및 통합 제어를 포함한다.
실제 하드웨어 제작과 실제 고양이 대상 검증은 이번 단계에 포함하지 않는다.

첫 구현(v0)은 낚싯대 위치 확인, 본체 접근·정지, 재인식, 파지·들어 올리기,
본체 정지 상태의 흔들기와 완료까지로 한정한다. 아래의 고양이 탐색·접근·멀어지기,
랜덤 회피 및 자동 놀이 모드는 이후 통합 요구로 유지한다.
v0의 장면 구성, 초기 시험값과 안전 개념은 [시스템·장면·안전 설계](system-design.md)에서 관리한다.

아래 미정 설정값은 구현·검증 전에 합의한다. 값이 정해지기 전에는 해당 수치 기준의
충족 여부를 확정하지 않는다.

## 2. 카메라 인식

| ID | 요구사항 | 검증 기준 |
| --- | --- | --- |
| VIS-01 | 시뮬레이션 카메라 영상을 인식 입력으로 사용해야 한다. | 영상 입력부터 인식 결과 출력까지 연결되는지 확인한다. |
| VIS-02 | 손잡이에 색상 표식이 있는 지정 장난감을 탐지하고 접근·파지에 필요한 위치와 방향을 추정해야 한다. | 합의한 거리·각도·조명 조건에서 탐지 성공률과 위치·방향 오차를 측정한다. |
| VIS-03 | 시뮬레이션의 고양이 대상을 탐지하고 위치와 로봇과의 거리를 추정해야 한다. | 고양이 대상의 위치를 바꾸며 탐지 성공률과 위치·거리 오차를 측정한다. |
| VIS-04 | 인식 결과에 좌표계, 측정 시각 및 유효 여부를 포함해야 한다. | 정상 탐지, 미탐지 및 오래된 결과를 구분하는지 확인한다. |
| VIS-05 | 접근·멀어지기 중 고양이 인식 결과를 갱신해야 한다. | 고양이 대상이 이동할 때 설정한 갱신 주기 안에 결과가 반영되는지 확인한다. |
| VIS-06 | 카메라로 팔·집게 위치를 인식하고 관측 자세 보정에 필요한 정보를 제공해야 한다. | 보이는 초기 자세와 가려진 초기 자세에서 유효 결과와 인식 실패를 구분한다. |
| VIS-07 | 영상과 파지 증거를 결합해 전용 장난감 보유 상태를 HELD / EMPTY / UNKNOWN으로 구분해야 한다. | 보유, 빈 집게, 가림, 다른 물체 파지 및 집게 근처 장난감 시나리오에서 잘못된 분기를 방지한다. |

## 3. 단계별 동작

| ID | 요구사항 | 검증 기준 |
| --- | --- | --- |
| SEQ-01 | 장난감을 인식한 뒤 로봇팔의 도달 범위 안에 들어오도록 접근해야 한다. | 카메라 추정 결과에 따라 접근하고 도달 범위 포함 여부를 확인한다. |
| SEQ-02 | 파지 직전에 장난감 위치·방향의 유효성을 확인하고 집게로 잡아 들어 올려야 한다. | 파지 후 장난감이 들어 올려지고 집게와 함께 움직이는지 확인한다. |
| SEQ-03 | 시작 시 전용 장난감 보유가 확인되거나 새로 파지에 성공한 경우에만 고양이 탐색을 시작해야 한다. | 초기 보유·미보유·파지 실패 시나리오에서 분기를 확인한다. |
| SEQ-04 | 장난감을 잡은 상태로 고양이에게 접근해야 한다. | 접근 중 파지가 유지되고 고양이와의 거리가 줄어드는지 확인한다. |
| SEQ-05 | 고양이와의 거리가 설정한 전환 거리 이하가 되면 멀어지기 단계로 전환해야 한다. | 전환 거리 전후의 상태 변화를 확인한다. |
| SEQ-06 | 멀어지기 단계에서는 고양이 위치를 갱신하며 거리가 증가하는 방향으로 이동해야 한다. | 장애물이 없고 고양이가 정지한 기준 시나리오에서 거리가 증가하는지 확인한다. |
| SEQ-07 | 멀어지기의 설정된 종료 조건에 도달하면 정지하고 완료 상태를 반환해야 한다. | 합의한 종료 조건에 따른 정지와 완료 상태를 확인한다. |
| SEQ-08 | 전원 입력 후 초기화하고 모드 선택을 기다린다. 매회 해당 모드의 시작 조건을 충족하면 팔·집게 확인, 관측 자세 보정, 보유 확인 순서로 수행해야 한다. | 모드 대기 중 이동 명령이 없고 두 모드 모두 보유 확인 후 탐색을 시작하는지 확인한다. |
| SEQ-09 | 초기 팔 보정 중 이동부를 정지하고 기존 파지를 유지해야 한다. | 장난감을 들고 시작해도 보정 중 집게를 열거나 장난감을 떨어뜨리지 않는지 확인한다. |
| SEQ-10 | 초기 보유 상태가 HELD이면 장난감 확보를 건너뛰고, EMPTY이면 장난감을 먼저 찾아 집어 들어야 한다. | 두 초기 조건에서 서로 다른 경로로 고양이 탐색에 도달하는지 확인한다. |
| SEQ-11 | 보유 여부가 UNKNOWN이면 정지 상태에서 재확인하고, 설정된 재시도 한도 초과 시 실패를 반환해야 한다. | 가림과 판단 불일치가 지속될 때 임의 분기 없이 종료하는지 확인한다. |
| SEQ-12 | 보정 후 미보유가 확인되면 최대 5분간 장난감을 탐색한다. 미발견으로 기한이 끝나면 정지·실패 안내 후 전원을 끄고 다음 예약도 취소한다. 고양이 탐색 시간 초과는 정지·실패로 처리한다. | 장난감 탐색 4분 59초에 발견하면 접근·파지가 가능하고, 5분간 미발견이면 OFF에 머무는지 두 모드에서 확인한다. |
| SEQ-13 | 전환 거리에 도달하면 장난감을 잡은 채 멀어지는 이동과 팔 놀이 패턴을 동시에 시작해야 한다. | 전환 전에는 놀이 동작이 없고 전환 후 이동과 팔 명령의 실행 시간이 겹치는지 확인한다. |

고양이가 로봇을 따라오는 경우에는 실제 거리 증가를 보장하지 않는다.
고양이가 이동한 경우의 회피 방향 갱신과 동작 결과도 별도 시나리오로 기록한다.

### 자동 놀이 시작 조건

| ID | 요구사항 | 검증 기준 |
| --- | --- | --- |
| MODE-01 | 꺼진 상태에서 전원 버튼을 한 번 누르면 부팅 후 대기한다. 켜진 대기 상태에서 한 번 누르면 바로 놀이, 두 번 연속 누르면 외출 모드를 시작한다. | 부팅 입력만으로 놀이가 시작되지 않고, 이중 누름 시 바로 놀이가 먼저 실행되지 않는지 확인한다. |
| MODE-02 | 외출 모드는 설계 기본값으로 활성화 즉시 첫 회를 시작하고 이후 2시간마다 한 회를 시작한다. 매회 장난감 보유 확인부터 10분이 지나면 정지한다. | 13:00에 활성화하고 13:03에 장난감을 집으면 정상 진행 시 13:13에 회차를 마치고 15:00에 다음 회차를 시작한다. |
| MODE-04 | 두 모드 모두 회차 최초 보유 확인 시점부터 놀이 시간을 잰다. 이미 보유했다면 팔 보정 후 확인한 시각, 새로 집었다면 파지 성공을 확인한 시각을 쓴다. | 장난감 탐색·접근 중에는 타이머가 시작되지 않고, 보유 확인 후 고양이 탐색·접근·회피 중에도 계속 흐른다. 사용자 정지 시 회차와 예약이 해제된다. |

## 4. 이동부 및 로봇팔 제어

| ID | 요구사항 | 검증 기준 |
| --- | --- | --- |
| DR-01 | 이동부는 전진·후진·제자리 좌우 회전 명령을 처리해야 한다. | 각 명령에 따른 위치와 방향 변화를 확인한다. |
| DR-02 | 이동 속도와 회전 속도를 설정된 범위로 제한해야 한다. | 제한을 초과한 명령에서도 설정값을 넘지 않는지 확인한다. |
| AR-01 | 로봇팔은 도달 가능한 목표 자세로 설정된 오차 안에서 이동해야 한다. | 목표 자세와 실제 자세를 비교한다. |
| AR-02 | 관절 범위 또는 도달 범위를 벗어난 목표를 거부하고 실패 원인을 반환해야 한다. | 범위 밖 명령에서 동작 거부와 실패 상태를 확인한다. |
| AR-03 | 집게는 열기·닫기 명령과 파지 상태 확인을 지원해야 한다. | 파지 성공·실패 및 이동 중 파지 상실을 구분하는지 확인한다. |
| AR-04 | 좌우 흔들기와 원 한 바퀴 그리기를 지정 패턴으로 제공하고, 멀어지는 동안 한 주기마다 실행 가능한 패턴 중 하나를 무작위로 골라야 한다. | 고정 난수 시드로 선택 순서를 재현하고, 두 패턴의 집게 끝 궤적과 파지 유지를 각각 확인한다. |
| AR-05 | 회피·정지·완료·파지 상실 시 놀이 동작을 중단해야 한다. | 패턴 실행 중 각 조건을 발생시켜 팔이 멈추고 회피 회전과 놀이 동작이 겹치지 않는지 확인한다. |

## 5. 랜덤 90도 장애물 회피

| ID | 요구사항 | 검증 기준 |
| --- | --- | --- |
| OBS-01 | 이동 방향의 장애물이 설정된 감지 거리 안에 들어오면 이동을 정지해야 한다. | 전방 장애물 시나리오에서 설정한 정지 응답 시간 안에 정지하는지 확인한다. |
| OBS-02 | 정지 후 좌·우 중 무작위로 한 방향을 선택하고 90도 회전을 시도해야 한다. | 선택 방향과 실제 회전각을 기록하고 회전각 오차를 확인한다. |
| OBS-03 | 회전 경로에 몸체·로봇팔·장난감의 충돌이 예상되면 회전을 시작하지 않거나 중단해야 한다. | 회전 공간이 막힌 시나리오에서 충돌 방지와 정지 상태를 확인한다. |
| OBS-04 | 회전 후 전방을 다시 확인하고, 장애물이 없을 때만 이동을 재개해야 한다. | 회전 후 전방이 열린 경우와 막힌 경우를 각각 확인한다. |
| OBS-05 | 회전 후에도 전방이 막혀 있거나 회전이 불가능하면 다시 무작위 방향으로 회피를 시도해야 한다. | 재시도마다 방향 선택과 장애물 재확인이 수행되는지 확인한다. |
| OBS-06 | 회피 시도 횟수가 설정된 최대값에 도달하면 정지하고 회피 실패를 반환해야 한다. | 양쪽이 막힌 상황에서 무한 반복 없이 실패로 종료하는지 확인한다. |
| OBS-07 | 회피 후 현재 단계의 대상을 재인식하고 동작을 이어가야 한다. | 장난감 접근 또는 고양이 접근·멀어지기의 목적에 맞게 동작을 재개하는지 확인한다. |

장애물 회피 중에는 회피 동작을 우선하므로 고양이와의 거리가 일시적으로 줄어들 수 있다.
고양이 자체도 충돌 방지 대상으로 취급한다.

## 6. 공통 제어 및 실패 처리

| ID | 요구사항 | 검증 기준 |
| --- | --- | --- |
| AUD-01 | 장난감 보유 상태가 판단 불가여서 재확인을 시작하면 지정된 안내음을 한 번 재생해야 한다. | 연속된 미확인 프레임에서 같은 안내가 반복되지 않고, 사용자가 재확인 중임을 들을 수 있는지 확인한다. |
| AUD-02 | 최종 실패 시 사용자에게 해당 원인을 음성으로 알려야 한다. | 보유 확인 한도 초과, 파지 실패, 고양이 탐색 시간 초과 등을 각각 발생시켜 원인에 맞는 안내가 한 번씩 들리는지 확인한다. |

- 원격 또는 사용자 입력으로 기본 동작을 조작할 수 있어야 한다.
- 모든 단계에서 사용자 정지 명령을 처리해야 한다.
- 장난감 파지에 실패하면 고양이 접근 단계로 전환하지 않아야 한다.
- 이동 중 장난감 파지를 상실하면 정지하고 실패 상태를 반환해야 한다.
- 현재 단계에 필요한 인식 결과가 없거나 유효 시간이 지나면 해당 자동 동작을 정지해야 한다.
- 탐색 상태는 대상 미검출 상태에서도 수행할 수 있으나 오래된 대상 좌표를 사용하지 않아야 한다. 장애물 확인이 불가능하면 탐색 이동을 정지해야 한다.
- 초기 팔 인식·보정 실패 시 탐색을 시작하지 않아야 한다.
- 장애물 회피 상태에서는 충돌 확인을 전제로 회전할 수 있으며, 대상 재인식 전에는 일반 이동을 재개하지 않아야 한다.
- 현재 단계와 실행 중·완료·정지·실패 상태 및 실패 원인을 제공해야 한다.
- 이동부와 로봇팔의 명령·상태 형식, 좌표계, 단위 및 시간 기준을 문서화해야 한다.

## 7. 시뮬레이션 및 검증 환경

- MuJoCo에서 모델을 로드하고 제어 소프트웨어와 연결해 물리 시뮬레이션을 실행해야 한다. 정상 흐름과 실패 시나리오의 검증은 이 환경에서 수행한다.
- 이동부, 로봇팔, 집게, 색상 표식 장난감, 고양이 대상, 장애물 및 카메라를 표현해야 한다.
- 로봇은 Stanford TidyBot을 기반으로 한다. v0 장면은 독립 낚싯대 세트, 받침대, 바닥과 로봇 카메라로 구성한다. 고양이·추가 장애물은 안전 시험 및 이후 통합에서 대체 모형으로 추가한다.
- 낚싯대 세트는 색상 표식 손잡이·막대·줄·끝 장난감으로 설계한다. 기존의 줄 없는 표식 막대는 파지 비교 시험용으로 구분하며, 이 시험으로 전체 낚싯대 세트 검증을 대신하지 않는다.
- 낚싯줄의 접촉·걸림에 대한 시뮬레이션 중단 동작은 확인하되, 실제 줄 얽힘 방지와 실제 고양이의 행동·흥미·놀이 효과는 검증 범위에 포함하지 않는다.
- 제어에 사용하는 장난감과 고양이의 위치·방향·거리는 카메라 영상에서 추정해야 한다.
- 시뮬레이터의 실제 대상 좌표는 제어 입력 대신 인식 오차 평가의 기준으로 사용해야 한다.
- 개발용 동작 시험에 한해 실제 좌표를 입력으로 사용할 수 있다. 해당 결과는 별도 표시하고, 카메라 입력이 필요한 요구사항의 충족 근거로 사용하지 않는다.
- 시뮬레이터의 접촉·결합 상태는 파지 성공 검증에 사용할 수 있다.
- 같은 초기 조건과 난수 시드로 회피 동작을 재현할 수 있어야 한다.
- 정상 흐름, 인식 실패, 파지 실패·상실, 고양이 이동, 회전 후 장애물, 회전 공간 부족 및 정지 명령을 검증해야 한다.
- 검증 결과에는 초기 조건, 설정값, 난수 시드, 입력, 기대 결과와 실제 결과를 기록해야 한다.
- 팀원이 문서화된 설치·실행 절차와 MuJoCo 버전 정보로 시뮬레이션을 실행할 수 있어야 한다.

## 8. 구현·검증 전에 확정할 항목

| 항목 | 결정할 내용 |
| --- | --- |
| 개발 환경 | MuJoCo 사용은 확정. 사용할 MuJoCo 버전, 언어, 주요 라이브러리 |
| 카메라 구성 | RGB 또는 RGB-D, 장착 위치, 시야, 멀어지기 중 고양이 관측 방법 |
| 인식 조건 | 표식 형태, 고양이 모델, 거리·각도·조명 범위, 성공률과 허용 오차 |
| 인식 시간 기준 | 갱신 주기, 결과 유효 시간 |
| 이동부 | 크기, 최대 이동·회전 속도, 장애물 감지 방법과 감지 거리 |
| 로봇팔·집게 | 관절 수와 범위, 도달 범위, 파지 조건, 속도·집게 힘 제한 |
| 통합 인터페이스 | 명령·상태 형식, 좌표계, 단위, 시간 기준 |
| 단계 전환 | 고양이 접근에서 멀어지기로 바뀌는 거리 |
| 동작 종료 | 바로 놀이의 회당 시간과 종료 조건 |
| 회피 설정 | 최대 시도 횟수, 회전각 허용 오차, 충돌 확인 범위 |
| 응답 기준 | 정지 응답 시간, 로봇팔 목표 자세 허용 오차 |
| 초기화·보유 분기 | 카메라 시야, 팔 관측 자세, 보정 허용 오차, 보유 확인 프레임 수·증거·재시도 한도 |
| 탐색 | 장난감·고양이 탐색 경로와 속도, 고양이 탐색 제한 시간 |
